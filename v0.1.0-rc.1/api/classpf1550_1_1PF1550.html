Result< InterruptEvents > ServiceInterrupts () noexcept
 Read and clear the pending interrupts: INT_CATEGORY, then each flagged group's status byte (copied out before the clear), then a write of the same bits to clear them, at most three passes. The result also holds every status bit that another call read since the last service (the latch). With GpioGet(), an interrupt mask that masks no source, INTB not asserted, an empty latch and no input limit check pending, the call returns an empty result without bus traffic. A status event that arrives between the read and the clearing write is cleared too when the chip clears on read (C3); keep the mask narrow. Detailed Description

template<I2cPort Port>
class pf1550::PF1550< Port >

Driver for one PF1550 on a platform port.

Lifecycle: construct with the configuration (no I/O), then EnsureInitialized(), the one start-up call: it validates the configuration, brings the bus up, checks DEVICE_ID and checks the charger the chip starts with against your Limits. Configure() then writes the blocks you asked for. Every call that touches the chip returns Error::NotInitialized until EnsureInitialized() has succeeded; no call starts the chip as a side effect.

Optional port hooks, found at compile time:

Hook Used for Without it
void DelayUs(uint32_t us) noexcept The DVS-done wait Compile error at the first call that waits
bool GpioSet(CtrlPin, GpioSignal) noexcept STANDBY pin: RequestStandby() RequestStandby() returns Unsupported
bool GpioGet(CtrlPin, bool&) noexcept INTB: IntbAsserted(), idle skip of ServiceInterrupts() IntbAsserted() returns Unsupported
bool GetLastFailure(I2cFailure&) noexcept Tell an absent chip (NoDevice) from a bus error (Bus) Every failure is Bus
void Log(LogLevel, const char*) noexcept One line per lifecycle event or failure Nothing is logged

A hook declared with the wrong signature is a compile error.

◆ EnsureInitialized()

template<I2cPort Port>
Result< void > pf1550::PF1550< Port >::EnsureInitialized ( )
noexcept

Start the driver: validate the configuration, bring the bus up, check DEVICE_ID = 0x7C and check the charger as found against Limits (the chip's start-up options turn the charger on with the fast-charge timer disabled, Table 85).

Sends: DEVICE_ID, OTP_FLAVOR (the DVS declaration of SW1 and SW2 is checked against Table 85 for a listed option), then the charger registers. It writes nothing otherwise. With AsFoundPolicy::MakeSafe and an unsafe charger found on, also one write of CHG_OPER (linear regulator only) and the same reads again.

After DEVICE_ID has passed, SetChargerMode(Off or LinearOnly), CheckChargerAgainstLimits() and CancelShutdownRequest() work even when this call then fails (an unsafe charger found on must always be switchable off).

Returns
Ok; the Validate() error; Bus or NoDevice (nothing acknowledged: needs the optional GetLastFailure() hook); DeviceIdMismatch; Refused (a DVS declaration that contradicts the part), Unsafe (a DVS declaration on an unlisted part without its acknowledgement); OutOfLimits or Unsafe for an unsafe charger under AsFoundPolicy::Report; VerifyFailed. The call can be repeated.

◆ EnterShip()

template<I2cPort Port>
Result< void > pf1550::PF1550< Port >::EnterShip ( ShipConfirm  )
noexcept

Request SHIP mode (GOTO_SHIP): every supply, VSNVS included, turns off.

Refused unless STATE_INFO is Run, Standby or Sleep and VBUS reads below UVLO and not valid. The chip enters SHIP only when VBUSIN is below 1.0 V, which the driver cannot measure (Table 83, ambiguity C6); with VBUS between 1 V and UVLO it ends in REGS_DISABLE instead, and GOTO_SHIP stays set (the bit is plain read/write, Table 138): it acts again at the next REGS_DISABLE. CancelShutdownRequest() clears it. Recovery from SHIP is by a charger or a battery attach. Not verified on hardware. Pass ShipConfirm{}: the tag is the caller's confirmation that every supply turns off.

Returns
Ok, Refused, Bus.

noexcept

Read and clear the pending interrupts: INT_CATEGORY, then each flagged group's status byte (copied out before the clear), then a write of the same bits to clear them, at most three passes. The result also holds every status bit that another call read since the last service (the latch). Returns
The status bytes as read (PWRUP_I is an event like the others), OutOfLimits (the limit is above Limits, the charger was switched off), VerifyFailed, DeviceReset, Bus, NotInitialized. After one of the errors the bits stay in the latch for the next call.
